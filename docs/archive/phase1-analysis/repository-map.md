# Repository Map

> Phase 1 repository archaeology artifact. Audited 2026-08-20. Code and fresh command output take precedence over historical documents.

## Repository Shape

The repository has no `packages/` directory and no top-level `src/`. Product code is split between one Tauri desktop application, Rust workspace crates, process workers, and packaging tools.

## Primary Runtime Entry Chain

```text
Vite/Tauri -> main.tsx -> AppProviders -> TanStack Router
  -> route/workbench component -> Query or Zustand
  -> DesktopBridge -> Tauri invoke -> command in src-tauri/lib.rs
  -> babel_application::Kernel -> storage/adapters/runtime/workers
  -> SQLite/CAS/project filesystem -> response -> Query invalidation/UI state
```

## Notable Boundaries

- Production core calls are centralized behind `DesktopBridge`; the fixture is gated by both `VITE_DESKTOP_BRIDGE=fixture` and development mode (`apps/desktop/src/main.tsx:24-31`).
- The Tauri layer is not a thin transport only. It directly manages project registry/settings JSON and workspace file paths (`apps/desktop/src-tauri/src/lib.rs:679-878`), so filesystem ownership is split between Tauri and `Kernel`.
- `apps/desktop/dist`, `target`, nested worker `target` directories and release binaries are generated evidence, not source architecture.
