## Top Architectural Warning

The core is substantially safer than the UI shell. The highest near-term risk is not missing Rust capability; it is the UI maintaining parallel session/status/settings projections without a single explicit reconciliation contract. Phase 2 documentation should make ownership, hydration and close/save invariants normative before more UI features are added.

## Phase 2 Documentation System Recommendation

Do not begin Phase 2 implementation from these analysis files directly. After review, establish versioned formal documents for: product capability matrix, runtime architecture and boundaries, domain glossary/schema, state ownership/hydration contract, IPC contract catalog, save/close/recovery invariants, testing strategy and release acceptance checklist. Each should link to executable gates and record an owner/date.
