# Babel Tower E2E 说明

本文只讲当前仓库里真正存在的 E2E 边界。先记住一条：现在能稳定跑的是 fixture 浏览器 E2E，不是真实桌面 E2E。

## 先说结论

- `pnpm test:e2e` 可运行。
- 它启动的是 Vite + fixture bridge，不是安装后的 Tauri 应用。
- 真实桌面 E2E 缺失，因此不能用当前 Playwright 结果证明文件系统、安装包、原生对话框或重启恢复。

## 当前可运行的 E2E

`apps/desktop/playwright.config.ts` 里写死了：

```text
VITE_DESKTOP_BRIDGE=fixture pnpm dev --host 127.0.0.1
```

这意味着 Playwright 起的是浏览器前端，桥接层由 `apps/desktop/src/test/fixture-app.ts` 提供假数据。当前单条 E2E 用例在 `apps/desktop/e2e/workbench.spec.ts`，它验证的是：

- 首页能打开。
- 能进入项目内容页。
- 能切换到单元页。
- 能切换到资源页。

这类测试适合验证页面结构、路由和局部交互，不适合验证真实 IPC 或系统行为。

## 真实桌面 E2E 目前怎么写、为什么还不能信

真实桌面 E2E 需要安装后的应用、真实 Tauri 桥接和某种系统级驱动。当前仓库里没有这条自动化链路，所以下面这些步骤只能作为目标，不是现成的通过态：

| 目标步骤        | 当前实现状态                    | 真实 E2E 状态 | 说明                                            |
| --------------- | ------------------------------- | ------------- | ----------------------------------------------- |
| 启动真实 Tauri  | 实现存在，`pnpm dev` 可手动启动 | Missing       | 还没有 installed-app 驱动                       |
| 创建项目        | 命令存在                        | Unverified    | 还没有真实桌面自动化                            |
| 导入内容        | 命令存在                        | Unverified    | 需要真实文件系统与桥接                          |
| 编辑并保存      | 命令存在                        | Unverified    | 需要实际修订链路                                |
| 重启并恢复      | 部分实现存在                    | Partial       | workspace state、tabs、dirty 和恢复 UI 还不完整 |
| 验证 filesystem | 实现存在                        | Missing       | 还没有把结果纳入桌面 E2E                        |
| OCR             | 开发路径存在                    | Unverified    | Linux 资源存在，真实桌面闭环未证实              |
| Export          | 核心实现存在                    | Unverified    | 没有真实桌面安装态证据                          |

## 你现在该怎么理解这些状态

- 看到 `fixture`，就只把它当作浏览器层测试。
- 看到 `Tauri` 或 `real desktop`，就必须额外要求安装态、文件系统和重启证据。
- 看到 `Partial`，就说明代码路径存在，但恢复语义还没有被完整证明。
