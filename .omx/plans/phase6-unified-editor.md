# 第六阶段计划：统一编辑器与连续资源工作流

## 当前进度

- [x] A：统一工作项、工作空间、导航值对象、活动 generation 查询和图片区域资源队列契约。
- [x] B：导航位置持久化、恢复和统一桌面工作台外壳基线。
- [x] C：版本化 IPC 最小闭环（项目打开、快照、译文保存、导航读取）。
- [x] D：本地项目库、项目打开和 TXT/Markdown/EPUB 导入命令。
- [~] E：系统文件选择器、资源队列、人工修正、真实图片预览、基础背景清理、确定性渲染核心、Linux x64 OCR、OCR 候选持久化和嵌字派生预览已完成；格式联合导出、缓存跨重启回显和最终 E2E 仍待完成。

当前 `TranslationStatus` 已冻结公共枚举；在状态命令和持久化落地前，应用投影仅根据当前译文区分“未翻译”和“草稿”，不会虚构“已翻译/已审校/受阻”状态。

## 目标

在不改变既有 `ResourceGraph`、TIR、稳定 `unit_id`、SQLite 权威存储和安全导出边界的前提下，建立跨 TXT、Markdown、EPUB 和图片资源的一致翻译体验。用户面对的是同一个翻译工作项，只是在长文、单元和资源三种观察方式之间切换。

## 成功标准

- 文本单元和图片文字区域共享 `unit_id`、译文、状态、撤销、搜索、保存和校验。
- 切换观察方式不重建工作台，不丢选区、光标、上下文、筛选或未提交草稿。
- 图片资源支持按稳定顺序连续处理区域和图片，前后项切换不需要返回文件列表。
- 关闭并恢复后能够回到准确工作项、区域、缩放和队列筛选。
- 导出从同一权威翻译状态读取文本和图片派生结果；原件不被覆盖。

## 范围

### 必须完成

1. 统一领域契约：`TranslationWorkItem`、`NavigationPosition`、资源关联和格式能力声明。
2. 统一工作台外壳：项目上下文、当前工作项、保存状态、撤销和前后导航。
3. 长文模式接入真实 `TranslationDocument`，支持章节窗口化和稳定单元锚点。
4. 单元模式接入同一模型，支持虚拟化、筛选和键盘导航。
5. 资源模式接入图片区域，支持 OCR 结果修正、人工译文、基础背景清理和基础嵌字预览。
6. 资源队列：按来源顺序、未完成和问题状态生成稳定队列，支持图片内区域连续导航。
7. 保存/恢复/校验/导出跨模式回归测试。

### 明确不做

- 机器翻译、生成式 AI 或自动改写。
- Photoshop 级图层、复杂蒙版、透视变换和高级背景重建。
- 自动字体识别和全自动风格还原。
- 新增格式适配器；本阶段只验证既有四种格式的统一契约。

## 实施顺序

### A. 契约冻结

- 为工作项补充统一读模型和命令模型。
- 明确文本 `TextRange` 与图片 `SpatialRegion` 的定位语义。
- 为每种格式补齐能力矩阵和导出前置条件。

退出条件：同一 `unit_id` 能从三种观察方式读取，且不存在格式专属译文状态。

### B. 工作台壳与导航

- 建立统一 `TranslationWorkbench` 状态机。
- 定义 `navigation_position` 的保存、恢复和路由映射。
- 统一上一项/下一项、保存、撤销、搜索定位命令。

退出条件：模式切换不触发全局重载，不改变权威修订序列。

当前结果：导航位置已由 schema 9 与核心单写者实现，并有跨重启回归测试；桌面端已完成路由、组件、设计令牌和页面骨架，IPC 最小闭环已经接入。项目库登记簿、项目打开、系统文件选择器、三种文本格式导入和资源工作流已接入。

当前结果补充：schema 10 已分离 OCR 可重建缓存与人工图片区域 revision；`babel-image` 已提供哈希保护、区域校验、平色背景清理和确定性 PNG 渲染核心。暂不构建任何 Linux/Windows 安装包。

6E3 当前结果：`Kernel::read_image_preview` 已通过 generation locator 读取并验证 CAS/EPUB 图片成员，Tauri `image_preview` 只返回受控 data URL，资源页已显示真实图片并叠加区域定位。`babel-ocr` 固定 Linux x64 ONNX Runtime/PP-OCRv6 tiny 资产哈希，并固化 `OcrProfile`、`OcrRequest`、`OcrEngine`、能力声明和统一 `OcrDocument`；`babel-ocr-worker` 的 `ProbeAssets` 与 `Recognize` IPC 已通过真实图片烟测。6E4 已增加 OCR 候选缓存的核心读写、模型指纹隔离、幂等和覆盖保护；Tauri worker 调度与资源页“重新识别”入口已接通，识别结果经 `Kernel` 持久化后回显。6E5 已接通人工译文到 CAS 派生 PNG、图片区域 revision 和资源页嵌字预览。6E6 已接入格式无关图片覆盖投影；EPUB 与 Markdown 均支持同图多区域合成，Markdown 文件路径导入会把相对图片纳入 CAS，文件导出会写出图片闭包。

IPC 结果：`apps/desktop/src-tauri` 暴露 schema v1 的桌面工作台命令，包括项目、导入、快照、资源、图片预览、OCR、嵌字预览、译文和导航边界；React 的项目打开、快照读取、单元列表、资源连续导航和译文保存已接入。由于浏览器预览不具备 Tauri runtime，预览模式保留只读降级数据。

### C. 图片连续工作流

- 建立资源队列和图片内区域队列。
- 实现前后项缩略图预加载、当前图高分辨率按需加载。
- 实现基础嵌字派生图和溢出/未完成校验。
- 将派生图片对象安全替换回 EPUB/Markdown 成员，并验证文本与图片联合导出。

退出条件：连续处理 100 个图片区域时无路由往返、无状态分叉，关闭后可精确恢复。

### D. 端到端验证

- Playwright 验证中文输入法、键盘导航、保存失败、恢复和跨模式跳转。
- 核心测试验证同一 `unit_id` 在文本、单元和图片视图中的一致性。
- 导出测试验证文本补丁和图片派生图同时生效，原件哈希保持不变。

## 性能预算

- 长文只加载当前章节窗口；单元列表必须虚拟化。
- 图片队列只预加载前后缩略图和元数据，避免一次读取整本 EPUB 图片。
- 编辑输入不等待完整导出或高分辨率合成；预览使用增量渲染，最终导出重新渲染。
- 模式切换不重新解析项目，不重建 SQLite 连接，不重置撤销历史。

## 阶段停止条件

只有当“章节文本 -> 关联图片 -> 连续区域 -> 下一资源 -> 关闭恢复 -> 文本返回 -> 安全导出”整条链路通过后，才进入后续高级图片排版或新格式接入。若其中任一环节产生第二套状态或需要文件级手工跳转，必须先修复统一契约。
