# Babel Tower 首版产品需求边界

## 1. 产品结果

Babel Tower 是面向个人译者的离线优先桌面翻译工作台。首版必须让用户在 Windows 与 Arch Linux 上，从 TXT、Markdown、EPUB 2/3 或其中的受支持图片开始，完成导入、人工翻译、图片文字处理、校验和导出，而无需账号、网络、命令行或插件知识。

## 2. 核心原则

1. 原件不可变：导入源对象永不就地修改，导出只产生新文件。
2. 一个项目真相：长文、结构化单元和资源工作空间共享内容单元、译文、状态、撤销和任务。
3. 人工译文：OCR 只识别原文；系统不生成或擅改译文。
4. 失败可恢复：编辑、任务和导出有明确事务边界，辅助进程失败不污染项目。
5. 格式能力内置：首版适配器由核心仓库维护，不以用户插件生态承担基本体验。

## 3. 首版用户故事

- 用户可导入 TXT、Markdown、EPUB 2/3，看到可翻译内容而不是容器结构。
- 用户可在三种工作空间之间切换，同一译文和状态立即一致。
- 用户可持续写作，看到保存状态，并在异常退出后恢复已确认保存的内容。
- 用户可识别 Markdown/EPUB 图片文字，手工填写译文并生成嵌字衍生图。
- 用户可搜索源文和译文，标记草稿、已翻译、已审校等状态并查看进度。
- 用户可在导出前看到结构、缺失译文、编码、图片和格式诊断。
- 用户可导出 TXT、Markdown 或 EPUB 新文件，原始文件保持不变。

## 4. 首版范围

### 4.1 格式

- TXT：UTF-8、UTF-8 BOM、UTF-16 LE/BE；其他可由 `encoding_rs` 表示的编码通过导入界面确认。保留 BOM、换行和最终换行策略。
- Markdown：CommonMark 基线；保留未修改字节、原有空白和扩展语法，翻译只替换已映射文本跨度。
- EPUB 2/3：解析 container、OPF、spine、XHTML、NCX/nav 和资源引用；只修改受支持的 XHTML 文本跨度及选定图片条目。
- Markdown/EPUB 混合内容：行内结构作为不可丢失 code；不支持或无法安全映射的结构阻止对应单元导出，不静默规范化。
- 图片：首版支持 PNG、JPEG、WebP 的 OCR 区域、人工译文和衍生图输出。

### 4.2 状态

- 单元状态：`untranslated`、`draft`、`translated`、`reviewed`、`blocked`。
- 任务状态：`queued`、`running`、`succeeded`、`failed`、`cancelled`、`interrupted`。
- 保存状态：`editing`、`saving`、`saved`、`error`；只有核心提交成功后显示 `saved`。

## 5. 明确非目标

- 机器翻译、生成式 AI、自动改写或自动润色。
- 云同步、账号、多人协作和在线素材依赖。
- 游戏引擎、音频、视频格式的首版实现。
- 任意 EPUB/Markdown 的像素级完全相同重建。
- 稳定的第三方插件 ABI 或插件市场。

## 6. 验收标准

1. 断网安装后可导入、编辑、保存、恢复、OCR、校验和导出首版格式。
2. 三个工作空间对同一单元的译文、状态和撤销结果一致。
3. 强制终止 OCR worker、导出任务或 UI 不会改变任何源对象。
4. 所有持久化编辑在核心返回成功后，应用重启可读取相同值。
5. 未修改项目导出时，TXT/Markdown 的源字节一致；EPUB 的未修改 entry payload 一致，容器满足 EPUB 结构规则。
6. 格式无法安全回写、目标编码无法表示译文、磁盘空间不足或源映射失效时，导出被阻止并给出本地诊断。
7. 安装包包含 OCR 模型、字体和必需运行时，首次启动不下载资源。
8. Arch 支持声明必须列出宿主 FUSE/glibc/WebKitGTK 前置条件；启动前失败不能由应用内提示替代，也不能宣称为零前置条件。

## 7. 延后决策

- 游戏引擎适配器的隔离和签名机制。
- 音频/视频时间轴内容模型。
- 跨设备同步与协作冲突模型。
- 公共扩展 SDK；在首版内部适配器稳定前不承诺 ABI。
