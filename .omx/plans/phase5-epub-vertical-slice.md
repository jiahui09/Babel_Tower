# Phase 5：EPUB 2/3 纵向闭环

状态：已完成（真实 Kernel 路径合同型 L 通过；极端文本型 L 限制已记录）
日期：2026-08-18
前置阶段：Phase 4 Markdown 纵向闭环已完成；完整安装包签发继续延后到 Phase 7。

## 1. 阶段目标

用 EPUB 2/3 证明多格式核心能够处理受约束的归档容器、多文档阅读顺序、嵌套资源关系、稳定重导入和安全重打包，而不把 ZIP、XML、XHTML 或 EPUB 私有模型写入公共协议或权威数据库。

完整闭环为：导入原始 EPUB、生成 ResourceGraph/TIR、人工保存译文、重启恢复、结构变化后绑定审查、冻结快照导出、重新导入验证。任何失败都不得修改源文件或覆盖已存在的导出。

## 2. 支持边界

### 首版支持

- EPUB 2：`META-INF/container.xml`、OPF 2.x、manifest、spine、NCX、XML/XHTML 内容文档。
- EPUB 3：EPUB 3.3 容器、OPF 3.x、manifest、spine、nav、XHTML 内容文档。
- UTF-8/UTF-16 XML 元数据；可编辑内容文档保守限定为可无歧义解析和回写的 XML/XHTML。
- CSS、字体、图片和其他未修改成员作为资源保存并保持引用关系。
- A 级：未修改成员内容与元数据可复用，已修改 XHTML 只做有界文本补丁。
- B 级：容器目录和压缩表示可能确定性重写，但语义、成员内容、媒体类型和阅读顺序保持。

### 拒绝或降级

- DRM、加密条目、未知压缩方法、损坏 central directory、重复规范化路径、绝对路径、`..` 路径穿越、符号链接式条目。
- 超过成员数、单成员大小、展开总量、压缩比、XML 深度、属性数或文本节点数预算的输入。
- 无法证明安全文本跨度、未声明脚本语义、无法保持保护结构的 XHTML 单元只读或阻止正式导出。
- EPUB 固定版式、媒体叠加、脚本交互、复杂 MathML/SVG 文本首版不声明可编辑支持；资源可以保留。

## 3. 架构不变量

1. EPUB 适配器独占容器、OPF、spine、nav/NCX、XHTML 和成员引用语义；核心只接收 ResourceGraph、TIR、locator、能力清单和验证结果。
2. 原 EPUB 作为不可变 CAS 对象保存；适配器只持有受限 ObjectHandle/StagingHandle，不取得项目目录能力。
3. 所有变长清单和抽取结果分页，所有读取受 deadline、取消、字节、节点和展开预算控制。
4. 稳定身份以规范化成员路径、文档结构路径、可见文本和邻域指纹生成；不得以 ZIP 成员序号或整书哈希作为唯一身份。
5. 只有 Exact 绑定自动继承；重复、拆分、合并、重排和歧义必须进入审查。
6. 导出绑定冻结的 generation、commit sequence、源对象哈希、成员清单哈希和 overlay 哈希。
7. 只补丁发生变化的 XHTML 文本范围；未修改成员不重新解析或语义序列化。
8. 候选容器完成结构、引用、阅读顺序和映射覆盖验证后才允许发布；失败候选不能成为正式结果。

## 4. 实施分解

### G1 契约、依赖与语料

- 选择并锁定 ZIP、XML/XHTML 解析依赖，记录许可证、MSRV、离线闭包和安全边界。
- 建立最小 EPUB 2、EPUB 3、嵌套路径、多章节、图片/CSS/字体、nav/NCX 黄金语料。
- 建立重复路径、路径穿越、绝对路径、加密、超高压缩比、超大成员和损坏目录的对抗语料。
- 固定项目实际声明支持的 W3C EPUB Test Suite 用例集合；外部验证器仅作阶段证据，不成为运行时依赖。

退出：支持矩阵、预算和 fixture 哈希可复现，依赖选择不突破 Rust 1.97 与单包离线约束。

### G2 EPUB 适配器与隔离 worker

- 新增 `babel-epub-adapter`，实现 signature probe、容器清点、根文件解析、manifest/spine/nav/NCX 编排。
- 生成 Container、Document、TextStream、Style、Font、Image 等节点以及 Contains、References、ReadingOrderAfter 边。
- 对 spine 中支持的 XHTML 提取可翻译文本跨度；标签、属性、链接目标、脚本、样式、实体边界等保持受保护。
- 新增 `babel-epub-worker`，沿用有界加载、分页清点/抽取、取消、deadline 和 IPC frame 上限。

退出：相同输入重复运行产生一致的资源图、阅读顺序、TIR 和 source unit key；恶意输入在预算内受控拒绝。

### G3 应用、存储与稳定重导入

- 在格式无关应用管线注册 EPUB manifest、worker 与公开 API，不新增 EPUB 专用权威表。
- 保存译文、关闭重开、查询和校验复用现有 SQLite 单写者与 revision 模型。
- 覆盖章节插入、删除、改名、重排、重复段落、段落拆分/合并和 nav 变化。
- 审查完成前旧活动 generation 保持可用；错误自动绑定必须为零。

退出：导入、保存、恢复和重导入审查闭环通过，任何歧义不静默继承译文。

### G4 安全重打包与验证

- 导出计划记录源成员目录、成员前置哈希、变更 XHTML 集合和期望全局约束。
- 对变化 XHTML 生成不重叠字节补丁；未变成员直接复制原始解压 payload，不做语义重写。
- 写出时保证 `mimetype` 首项、未压缩且值正确；重建 central directory 并保持成员路径、媒体类型和必要顺序。
- 验证候选 ZIP、container.xml、OPF、manifest/spine、nav/NCX、相对引用、成员哈希和翻译映射覆盖。
- 候选写入 staging，验证后由应用层流式、原子 no-clobber 发布；失败或中断不覆盖源文件或已有正式导出。

退出：导出可重新导入且资源图/阅读顺序一致；未改成员 payload 哈希一致；故障注入证明失败不覆盖。

### G5 性能、兼容与签发

- L 语料：500 MiB 压缩包、5,000 成员、展开 2 GiB、10 万翻译单元；生成器和固定哈希纳入阶段资产。
- 门槛：首批内容不超过 8 秒，完整导入不超过 90 秒，导出不超过 60 秒，导入峰值 RSS 不超过 1.5 GiB。
- 运行 EPUB 专项、统一适配器契约、稳定身份、恢复、workspace test、Clippy、fmt 和架构检查。
- 使用至少两种独立阅读器或验证器做 smoke check，固定版本并记录；Linux 环境不宣称 Windows 实机验证。
- 输出 `PHASE5.md`、机器可读性能结果、支持矩阵、QA 报告和独立代码/架构审查。

退出：所有安全不变量和绝对预算有新鲜证据；任何未通过项不得包装为“支持 EPUB”。

## 5. 阶段停止条件

- 任一输入可以越过容器根目录、绕过展开预算或造成无界内存增长。
- 错误自动绑定率不为零。
- 导出会覆盖源对象、在验证前发布或改变未声明成员内容。
- EPUB 私有 AST/DOM/ZIP 表进入公共协议或 SQLite 权威模型。
- 为通过性能门降低 SQLite FULL 保存、跳过哈希/验证或引入无界并发。

出现上述任一项，停止扩展覆盖面并先修复核心链路。Phase 5 不执行完整 NSIS/Arch 安装、升级、卸载和断网发布闭包。
