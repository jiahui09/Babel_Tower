# 测试规范：Babel Core v2 多格式高性能核心

状态：架构师与评论员已批准，可进入 Phase 0 架构证伪  
版本：1.0

关联 PRD：`.omx/plans/prd-multiformat-core-v2.md`

## 1. 测试目标

本规范验证五类发布声明：

1. 人工译文、绑定和原始对象在崩溃、断电、适配器失败及迁移中保持安全。
2. TXT、Markdown、EPUB 和图片遵循同一个适配器契约并达到公开支持等级。
3. 长文、单元、资源三种观察模式共享同一项目与单元状态。
4. 交互热路径在大型项目和后台负载下仍满足预算。
5. 完整安装包在 Windows 与 Arch Linux 断网环境中完成导入到导出。

当前仓库没有实现代码，本文件定义未来验收方法，不代表测试已经通过。

## 2. 测试分层与门禁

| 层级 | 目标 | 每次提交 | 每夜 | 发布 |
| --- | --- | ---: | ---: | ---: |
| 单元/属性 | ID、TIR、命令、路径、状态机 | 是 | 是 | 是 |
| 契约/黄金 | 每个适配器统一行为 | 受影响格式 | 全量 | 全量 |
| 集成 | SQLite/CAS/DAG/IPC/恢复 | 受影响模块 | 全量 | 全量 |
| E2E | 用户链路与跨视图一致性 | 核心 smoke | 全量 | 全量双平台 |
| 模糊/恶意 | 解析器和协议边界 | 短时 corpus | 长时 | 24h/关键目标 |
| 故障注入 | 崩溃窗口与原子性 | 关键状态机 | 全量矩阵 | 全量矩阵 |

发布门禁不得通过降低 SQLite 持久性、跳过哈希/验证、减少语料或提高机器规格来规避。

## 3. 固定参考环境

### 3.1 硬件基线

- 4 核 8 线程 x86-64 CPU。
- 16 GiB RAM。
- PCIe/NVMe SSD，项目与临时目录在同一文件系统。
- 1920×1080 显示，60 Hz。
- 无其他重型前台任务，关闭测试机自动更新和索引干扰。

另设 ARM64/高 DPI/机械硬盘为兼容性观察环境，不替代基线签发。

### 3.2 平台

- Windows 11 当前项目支持版本，NTFS。
- Arch Linux 发布签发时冻结的快照与内核，ext4 或项目明确支持的主文件系统；另在当前滚动版本跑兼容性 smoke。
- 所有性能测试使用 release 构建与正式安装包等价配置。

### 3.3 固定语料

| 代号 | 内容 | 用途 |
| --- | --- | --- |
| S | 10 MiB TXT，约 10 万行/单元，混合 LF/CRLF 测试变体 | 文本导入、分页、搜索、保存 |
| M | 100 MiB Markdown，25 万单元，2,000 张引用图片 | 结构保护、增量、图片引用 |
| L | 500 MiB EPUB，5,000 成员，展开 2 GiB，10 万单元 | 容器、内存、导出、恶意限制 |
| I | 200 张 2000×3000 图片，每张 20 区域 | OCR、调度、内存、取消 |
| B | 绑定变异集：插入、删除、移动、拆分、合并、重排、格式升级 | 译文保留与错绑检测 |
| U | Unicode/CJK 集：组合字符、emoji、竖排、单字/双字、标点 | 边界、搜索、光标、导出 |

生成器固定 seed、版本和 SHA-256。另设经过许可且去标识的真实结构语料；真实语料结果只做补充，不能替代可复现固定语料。

## 4. 数据安全测试

### DS-01 原件不可变

步骤：导入每种格式，执行编辑、OCR、校验、导出、失败导出和恢复。  
断言：源路径内容 SHA-256、长度、权限和修改时间不因 Babel 写操作改变；所有输出位于新路径。

### DS-02 译文修订耐久

步骤：对同一单元连续提交 1,000 次编辑，随机在事务提交前、WAL 同步前后、确认发送前后终止进程。  
断言：恢复结果只能是最后一个已耐久确认版本或明确的未确认候选；不得出现部分 UTF-8、重复 revision 或确认后丢失。

### DS-03 命令幂等

步骤：对相同 `command_id` 在超时、断线和进程重连后重复发送。  
断言：只产生一个逻辑修订和一个 receipt；返回值一致。

### DS-03A 草稿恢复

对绑定 `project_id + unit_id + base_revision_id + client_session_id` 的 DraftSession 随机在本地输入、草稿确认、耐久命令发送和窗口关闭处终止。断言草稿可恢复但不推进 `commit_sequence`、不进入导出、不能覆盖已确认修订；基准修订变化时必须进入差异裁决。

### DS-04 对象发布原子性

故障点：临时创建、流式写中、文件同步前后、最终重命名前后、父目录同步前后、SQLite 引用前后。  
断言：数据库永不引用缺失/半写对象；重复恢复得到相同 SHA-256；孤立完整对象只由保守 GC 回收。

### DS-05 活动导入代

步骤：在清点、每个抽取批次、绑定、最终验证和激活事务处终止。  
断言：旧活动代始终可打开；不完整代不可作为正式可编辑项目；恢复/清理幂等。

### DS-06 备份闭包

步骤：并发编辑、索引和 OCR 时创建备份；在新路径、另一平台恢复。  
断言：数据库 `integrity_check` 通过；所有可达对象存在且哈希匹配；译文头和修订链一致；缓存可重建。

并发 GC、导入和导出重复执行，随机在固定 `commit_sequence`、创建 backup root pin、复制数据库、复制对象和释放 pin 处终止。断言 pin 与根在同一权威事务建立，GC 在校验完成前不能清理闭包对象。

### DS-07 缓存全删

步骤：保留权威 SQLite、源对象和人工译文对象，删除 DAG 派生结果、FTS、缩略图、OCR 缓存和预览。  
断言：项目可打开；重建后单位、译文、状态、绑定和导出结果语义一致。

### DS-08 GC 安全

步骤：在活动项目、旧代、运行任务、备份租约和导出快照组合下运行 dry-run 与实际 GC，并在标记/清扫各阶段终止。  
断言：所有根可达对象保留；清扫幂等；宽限期内新引用不会被删除。

## 5. 身份与绑定测试

### BI-01 稳定重抽取

对相同源对象、适配器构建和配置重复抽取 100 次。  
断言：资源键、源单元键、TIR 内容哈希、阅读顺序和定位器字节完全一致。

### BI-02 结构变异

对 B 语料逐项应用空白、前置章节、同文移动、段落拆分/合并、重复句插入、标题改名和图片重排。  
断言：

- 无语义变化的变异 `Exact + Shifted` 覆盖率 ≥ 99.9%。
- 所有重复句歧义不得被自动绑定。
- 负例中的错误自动绑定率必须为 0；`Exact + Shifted` 覆盖率不能抵消任何错绑。
- `Ambiguous` 与 `Orphaned` 的旧译文仍可访问。
- 不允许以当前序号作为唯一身份依据。

另测 `SourceUnitIdentitySpec` 的规范化版本、候选证据、人工 `binding_decision` 账本、重复句、近似句、拆分/合并和阈值相同候选；`Shifted` 首版默认不自动继承，除非用户显式确认策略。

### BI-03 身份算法升级

步骤：用 `identity_version N` 导入并翻译，再以 `N+1` 预演重新绑定。  
断言：旧代不被原地改写；差异报告可重复；未确认前活动代不切换；回滚后译文头不变。

### BI-04 源文件新版本

步骤：导入作者修订版，包含增加、删除和改写。  
断言：精确继承、位置漂移、歧义和孤立分类正确；人工裁决产生新绑定证据；旧修订链不复制或丢失。

## 6. TIR 与编辑命令测试

### TIR-01 结构不变量

属性生成随机合法/非法 token 序列。  
断言：嵌套、唯一 tag key、占位符数量/类型、引用目标和字素边界验证准确；非法序列不能进入权威修订。

### TIR-02 Unicode 边界

使用 U 语料执行删除、替换、移动、撤销和重做。  
断言：不拆分扩展字素簇、代理项或组合字符；源字节偏移与显示范围明确分离。

### TIR-03 撤销/重做

生成包含文本、受保护 token、状态、术语和批注的随机命令序列，再完全撤销/重做。  
断言：物化头与参考模型一致；历史不删除；跨单元 undo group 原子。

### TIR-04 并发前置条件

模拟旧 `commit_sequence`/旧 unit head 的命令。  
断言：核心拒绝静默覆盖并返回当前头；可重放命令保持语义。

## 7. 适配器统一契约套件

每个适配器必须注册同一套契约；缺少适用测试的能力不能声明对应等级。

### AC-01 探测

- 扩展名正确/错误/缺失。
- 签名字节截断、伪造、超大探测头。
- 在 `budget` 内返回且不读取未授权范围。

### AC-02 清点与分区

- 分页游标稳定、无遗漏、无重复。
- 不同页大小与中断恢复产生相同资源图哈希。
- 超过成员数、深度、展开比和总字节限制时受控失败。

### AC-03 确定性抽取

- 相同输入/版本/配置跨运行产生相同 TIR 与私有产物哈希。
- 分区顺序变化不改变规范化合并结果。
- 取消后无权威部分提交。

### AC-04 无修改往返

- A 级：未修改区域满足声明的字节/payload 等价规则。
- B 级：输出语义等价，所有规范化差异属于清单列出的类别。
- C 级：正式导出被阻止并给出用户可理解原因。

### AC-05 有界修改往返

对首、中、尾、重复内容、跨 token、空译文、超长译文和占位符执行修改。  
断言：只改变计划允许的资源；前置哈希不符时拒绝；重新导入得到对应译文。

### AC-06 错误隔离

工作进程 panic、OOM 配额、超时、协议错误和输出哈希错误。  
断言：核心仍可保存/打开项目；任务熔断；临时文件和租约可回收。

### AC-07 清单一致性

断言：协议范围、身份版本、支持格式、能力等级、安全上限和测试结果一致；产品支持矩阵从此生成。

## 8. 格式专项测试

### 8.1 TXT

- UTF-8 BOM/无 BOM、UTF-16LE/BE、明确支持的本地编码。
- LF/CRLF/CR、末尾换行、空文件、超长行、NUL/二进制误判。
- 编码不确定时不得擅自选择导致不可逆损失。

### 8.2 Markdown

- CommonMark 0.31.2 规范示例中的块/行内结构。
- 代码块/行内代码、链接目标、图片目标、HTML、转义、实体、引用、列表、表格扩展子集。
- 文本变化不破坏 protected token；未改源码范围满足支持等级。
- 结构移动与重新绑定使用 B 语料。

### 8.3 EPUB 2/3

- W3C EPUB Test Suite 中项目声明支持的用例集合。
- `mimetype`、META-INF/container.xml、OPF manifest/spine、NCX/nav、XHTML、CSS、字体、图片和相对引用。
- ZIP 重复路径、绝对路径、`../`、加密条目、超高压缩比、超大成员、损坏 central directory。
- 未改成员 payload 复用；导出后重新导入资源图和阅读顺序一致。
- 至少两种独立阅读器/验证器 smoke check；外部工具版本固定并记录。

### 8.4 图片/OCR

- 支持图片编解码、EXIF 方向、色彩空间、超大像素和损坏文件。
- 识别结果与人工译文字段/状态不可混淆。
- 区域多边形、阅读顺序、旋转/竖排、重叠和边界裁剪。
- OCR 取消/崩溃/内存超限不影响文本保存。
- 原图哈希不变，衍生图可追溯到原图、布局配置和人工译文快照。

## 9. DAG 与增量测试

### DAG-01 键完整性

改变每个键分量：输入对象、stage schema、适配器构建、配置和依赖输出。  
断言：应失效的节点必失效；无关平台/配置不导致污染。

### DAG-02 投影防火墙

场景：改单元译文、改术语、改图片区域、升级 Markdown 适配器、删除缩略图。  
断言：失效节点集合与期望图完全一致；单译文变化不触发源解析、无关资源 OCR 或全项目重抽取。

### DAG-03 绿色重算

使上游元数据变化但输出投影哈希相同。  
断言：下游保持 Ready，不执行无意义重算。

### DAG-04 失败与重试

随机在队列、运行、对象发布和记录 Ready 之间终止。  
断言：状态机可恢复；副作用不被错误缓存；失败退避不会阻塞 P0/P1；过期 lease/fencing token 不能写入 Ready；并发相同 ArtifactKey 只有一个 owner。

### DAG-05 复杂度门禁

在 1千/1万/10万/25万单元项目中重复单字符编辑、状态更新、视图切换。  
断言：触达的数据库行、DAG 节点和 IPC 字节保持常数或与可见窗口相关，不随全项目线性增长。

## 10. IPC 与安全测试

### IPC-01 版本兼容

- 当前核心与当前/前一 minor 工作进程握手。
- major 不兼容明确拒绝；未知可选字段被安全忽略；删除 tag 不复用。

### IPC-02 帧与流

- 0 字节、最大合法、超 4 MiB、截断、负逻辑长度、重复/乱序 chunk、错误哈希、信用耗尽。
- 断言内存有界、连接受控终止、无死锁、无权威部分提交。

### IPC-03 句柄权限

工作进程尝试读取未授权对象/范围、遍历路径、写非 staging 路径。  
断言全部拒绝并留下不含正文的安全诊断。

### IPC-03A 端点认证

测试随机 endpoint、Unix `0600`、Windows 当前用户 ACL、错误/过期/跨项目 capability token、旧 session nonce 和伪造 worker。断言未授权连接不能建立会话，授权范围不能扩大。

### IPC-04 恶意输入

对 ZIP、XML/XHTML、Markdown、图片和 Protobuf 入口进行覆盖引导模糊测试。  
断言无 core 崩溃、未定义行为、无界分配或目录逃逸；worker 崩溃被隔离。

## 11. 调度与交互测试

### SCH-01 优先级隔离

同时运行 L 导入、I OCR、全量索引和 EPUB 导出，持续执行输入、保存、搜索、模式切换。  
断言：P0/P1 满足性能预算；P3 有进展且无永久饥饿。

记录 writer 队列、每批行数/墙钟时间、WAL 大小和 checkpoint busy；P3 批次必须在声明边界让出，P0 保存必须在下一批边界获得服务，FTS/索引不能延迟译文 FULL 提交。

### SCH-02 过度订阅

监测 Tokio、Rayon、工作进程线程数、CPU、RSS 和 page fault。  
断言：总并发遵循资源治理器；不能出现每层按逻辑核独立扩容。

### SCH-03 内存配额

任务低报/超出预估内存，OCR 达到 1.5 GiB，磁盘暂存不足。  
断言：新重任务不启动或当前任务受控失败；核心与已保存译文保持可用。

### SCH-04 取消

在每个分页/分块边界取消导入、搜索、OCR、验证、导出。  
断言：目标时间内停止，释放信用/租约；导出已发布结果不受影响。

## 12. 导出事务测试

### EX-01 快照隔离

导出冻结后继续编辑 1,000 次。  
断言：输出只含冻结序列译文；导出记录准确；下一次导出包含新版本。

### EX-02 前置哈希

计划生成后篡改源对象句柄、适配器私有产物或 staging 文件。  
断言：materialize/verify 拒绝，不能发布。

### EX-03 故障矩阵

在冻结、校验、计划、写每个 chunk、文件同步、目录同步、重命名和记录事务处终止。  
断言：旧结果不被半覆盖；可恢复候选必须重新验证；最终状态唯一且幂等。

追加故障点：发布原子重命名成功后、`export_record` 事务提交前。启动对账必须使用 `publish_intent` 和候选哈希得到确定状态。

### EX-04 重新导入

导出结果作为新源导入。  
断言：格式有效、阅读顺序一致、受支持译文完整、protected token/引用不丢失。

### EX-05 路径安全

测试同路径、符号链接、保留名、超长路径、无权限、磁盘满和跨文件系统目标。  
断言：禁止源路径覆盖；无法原子重命名时采用明确的复制-同步-发布策略并记录限制。

## 13. UI/E2E 逻辑测试

### UI-01 同一对象跨视图

从长文当前句依次切到单元、关联图片、再返回。  
断言：同一 `unit_id`、选择、未提交输入、状态和撤销组保持；无对应资源时就地说明，不跳转循环。

### UI-01A 图片资源连续工作流

从 EPUB 章节文本跳转到关联图片区域，连续完成当前图片的多个区域，再进入下一张图片。

断言：资源队列按稳定阅读顺序提供前后项；区域按 `reading_order` 排列；切换不返回文件列表、不重建工作台、不丢失未提交输入；前后图片只加载缩略图和识别元数据，当前图片加载高分辨率预览；资源队列位置、区域和缩放写入 `navigation_position`。

### UI-01B 图片资源恢复与导出

在图片区域存在未提交草稿时关闭应用，重新打开并恢复，再切回长文观察方式并导出 EPUB。

断言：恢复到相同 `unit_id`、`resource_id`、`region_id`、筛选和缩放；译文和派生图片同时进入导出快照；原始图片哈希和原始 EPUB 哈希不变；嵌字失败时不提交半成品并显示可操作问题。

### UI-02 恢复入口

正常关闭、未确认输入、核心崩溃、worker 崩溃、未完成迁移分别打开项目。  
断言：正常项目直接回到上次工作点；需要裁决时进入恢复决策，不强制每次经过项目总览。

附加：模拟草稿存在、基准修订已变化、核心断线和窗口关闭失败；草稿不得覆盖已确认修订。

### UI-03 查询竞态

快速切换项目/章节/模式并人为延迟旧请求。  
断言：旧 `commit_sequence` 结果不能覆盖新页面；无重复路由和返回循环。

### UI-04 保存语言

断言界面区分“正在编辑/等待保存/已安全保存/保存失败”；不能在 FULL 提交前显示已保存。

### UI-05 键盘与可访问性

完整翻译循环可用键盘完成；焦点顺序稳定；组件库对话框、菜单、工具提示、错误摘要和快捷键冲突通过检查。

## 14. 性能基准协议

### 14.1 测量原则

- 微基准用 Criterion 或同等级统计框架，至少包含预热、离群说明和置信区间。
- 交互指标每个场景至少 500 次操作，报告 p50/p95/p99 与最大值。
- 导入/导出宏基准每平台每语料至少 5 次独立运行，首批/完整导入和导出均以 `max(run)` 作为发布上限，同时报告 median、p95 近似值和波动；冷缓存需重启应用并按平台记录清理方法。
- RSS 采样间隔 ≤ 100 ms，记录 core、UI、每个 worker 和总值；峰值定义为测量窗口内进程 RSS 总和的最大值，不计文件缓存，测试机记录 swap/page fault。
- 空闲 CPU 定义为应用所有进程 10 秒窗口的累计 CPU 时间 / 逻辑核数 / 窗口时间，Windows 使用 process CPU time，Linux 使用 `/proc` 进程时间；记录不可变 OS 镜像或快照、内核/构建号和硬件固件。
- 所有结果附 commit、构建配置、硬件、OS、语料哈希和原始机器可读文件。

### 14.2 发布预算

| ID | 场景 | 预算 |
| --- | --- | --- |
| PERF-01 | 输入到画面 | p95 ≤ 16.7 ms，p99 ≤ 33 ms |
| PERF-02 | FULL 保存确认 | p95 ≤ 300 ms，p99 ≤ 750 ms |
| PERF-03 | 热/冷模式切换 | p95 ≤ 100/250 ms |
| PERF-04 | 可见页查询 | p95 ≤ 50 ms |
| PERF-05 | 10 万单元搜索首屏 | p95 ≤ 150 ms |
| PERF-06 | 10 万单元冷打开可编辑 | p95 ≤ 3 s |
| PERF-07 | S/M/L 首批内容 | 每平台每语料 5 次，`max(run)` ≤ 1/3/8 s |
| PERF-08 | S/M/L 完整导入 | 每平台每语料 5 次，`max(run)` ≤ 3/20/90 s |
| PERF-09 | M/L 完整导出 | 每平台每语料 5 次，`max(run)` ≤ 15/60 s |
| PERF-10 | 10 万单元空闲 RSS，无 OCR | 10 秒窗口进程 RSS 总和峰值 ≤ 400 MiB |
| PERF-11 | L 导入峰值 RSS，无 OCR | 测量窗口进程 RSS 总和峰值 ≤ 1.5 GiB |
| PERF-12 | OCR worker 峰值 RSS | worker 进程 RSS 峰值 ≤ 1.5 GiB |
| PERF-13 | 空闲 10 秒后 CPU | 10 秒累计应用 CPU / 逻辑核 ≤ 1% |

### 14.3 回归规则

- 微基准相对基线退化 >10% 且统计显著：阻塞合并，除非审查证明不影响产品路径。
- 任何绝对预算失败：阻塞发布。
- 性能改动不得降低数据安全测试覆盖或持久性配置。
- 修改预算必须新增 ADR，附至少两个平台的原始结果和用户影响说明。

## 15. 安装、升级和离线测试

### PKG-01 全新安装

在无开发工具的干净 Windows/Arch 虚拟机安装。  
断言：Windows 单一安装器在系统未预装可用 WebView2 时，通过包内 Evergreen offline installer 完成安装；Arch 单一 AppImage 在声明的最低系统 ABI/图形基线上直接启动。两者均无需账号、命令行、包管理器或网络；TXT→导出可完成。

从真实发布下载产物而非构建目录开始测试。Arch 产物必须保留 AppImage 可执行位，或使用保留 Unix mode 的单一签名 `.tar.zst`；通过图形文件管理器解包/启动，不允许测试脚本先执行 `chmod` 或安装缺失包。

### PKG-02 断网链路

系统级阻断网络，执行 TXT/Markdown/EPUB 导入、翻译辅助、OCR、保存、关闭、恢复、校验和导出。  
断言：功能可用；无无限等待或隐藏联网重试。

在安装前即通过系统防火墙/网络命名空间阻断所有出站连接，并记录 DNS、TCP/UDP 和子进程。断言安装器、WebView2 offline installer、AppImage、OCR、适配器和首次启动没有网络请求；缺少任何包内组件时必须在构建门禁失败，不能运行时补下载。

### PKG-03 升级

从每个受支持旧项目版本升级，分别在迁移各阶段终止。  
断言：有迁移前备份；可恢复/回滚；旧项目不被唯一副本覆盖。

### PKG-04 卸载

断言：默认不删除用户项目和导出文件；运行时缓存行为明确；再次安装可打开项目。

### PKG-05 完整性

断言：Windows 安装器包含 WebView2 Evergreen offline installer；Arch AppImage 包含 WebKitGTK 4.1 与声明的应用运行库。两个产物都包含适配器、OCR 运行时/模型、字体资源、许可证、版本清单和 SBOM；逐项文件哈希与发布清单一致，双平台外部 ABI 先决条件有自动检查和用户可读错误。

Windows 对包内和安装后全部 EXE/DLL 执行 PE 静态导入枚举，并通过系统加载事件采集首次启动、worker、OCR 与各适配器探针的实际加载 DLL；结果只能属于包内文件、嵌入式 WebView2 安装结果或版本化 Windows 系统 DLL/API-set 白名单。MSVC/UCRT 等非白名单运行时必须由应用本地携带或由安装器离线安装。Linux 使用 `readelf`/`lddtree` 等静态枚举并执行端到端运行时加载跟踪；结果只能属于 AppImage 内文件或版本化内核、glibc/系统 ABI、图形会话与驱动接口白名单。两个平台的白名单、包内文件、静态闭包、实际加载集合和未知差集进入机器可读证据包；未知差集非空即阻塞签发。

## 16. 架构适应性测试（Phase 0 必须先做）

| 原型 | 要回答的问题 | 失败触发 |
| --- | --- | --- |
| SQLite 写入/WAL | FULL 保存与后台长读能否满足 PERF-02 | 调优后 p99 仍失败才讨论存储 ADR |
| 10 万单元查询/FTS | 分页、搜索、更新体积是否可控 | FTS/CJK 不达标触发 tokenizer ADR |
| CAS 发布/GC | 跨崩溃是否安全、吞吐是否足够 | 协议不变量失败则停止后续开发 |
| Protobuf IPC | 分页和句柄后复制成本是否仍显著 | profile 证明序列化占主导才比较零拷贝 |
| Markdown 绑定 | 结构变异下能否防错绑 | BI-02 失败则重做身份方案 |
| 资源治理 | L+I 后台负载下交互是否稳定 | P0/P1 失败则重做调度，不堆线程 |
| 双平台离线包闭包 | 真实下载件能否在干净禁网镜像安装、图形启动并加载内置 worker/OCR/适配器，且 Windows PE/DLL 与 Linux ELF/动态库闭包无白名单外依赖 | 任一平台需联网、补装运行时、Arch 需 `chmod` 或未知差集非空，则停止 Phase 1 并重做打包/依赖方案 |

Phase 0 的离线包原型必须来自正式发布流水线的真实下载件，而不是构建目录。允许使用专用最小 UI 和组件加载探针，不要求提前实现 TXT 完整业务链路；但 PKG-01 中安装/启动边界、PKG-02 的安装前禁网监测、PKG-05 的双平台依赖闭包和 Arch 执行位断言均不可豁免。Phase 3 再把已验证的包边界升级为 TXT 全链路 E2E。

## 17. 证据与签发

每个阶段的验收包必须包含：

- 测试命令、commit、平台和退出码。
- 失败/跳过列表及负责人。
- 性能原始 JSON/CSV、摘要和基线差异。
- 语料与安装包 SHA-256。
- 故障注入矩阵结果。
- 当前格式支持矩阵。
- 已知风险和对应 ADR。

签发顺序：实现负责人提交证据 → 测试工程师独立复跑 → 架构/代码审查确认不变量 → 工程总负责人批准阶段退出。任何“未运行”都必须写明，不能等同通过。
